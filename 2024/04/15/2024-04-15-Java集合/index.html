Java集合

泛型

<>用于指定数据结构存储的类型（只能是引用类型）。如：List<Integer>。List<int>错误

Collection

  • Collections（和 Collection 区分）：提供了一系列操作集合的静态方法，可以实现对集合元素的排序、查询、修改等操作。

List

接口：java.util.List<>。

实现：

  • java.util.ArrayList<>：变长数组
  • java.util.LinkedList<>：双链表

函数：

  • add()：在末尾添加一个元素

  • clear()：清空

  • size()：返回长度

  • isEmpty()：是否为空

  • get(i)：获取第 i 个元素

  • set(i, val)：将第 i 个元素设置为 val

栈

类：java.util.Stack<>

函数：

  • push()：压入元素

  • pop()：弹出栈顶元素，并返回栈顶元素

  • peek()：返回栈顶元素

  • size()：返回长度

  • empty()：栈是否为空

  • clear()：清空

队列

接口：java.util.Queue<>

实现：

  • java.util.LinkedList<>：双链表

  • java.util.PriorityQueue<>：优先队列

    • 默认是小根堆，大根堆写法：new PriorityQueue<>(Collections.reverseOrder())

函数：

  • add()：在队尾添加元素

  • remove()：删除并返回队头

  • isEmpty()：是否为空

  • size()：返回长度

  • peek()：返回队头

  • clear()：清空

Set

接口：java.util.Set

实现：

  • java.util.HashSet：哈希表
  • java.util.TreeSet：平衡树

函数：

  • add()：添加元素

  • contains()：是否包含某个元素

  • remove()：删除元素

  • size()：返回元素数

  • isEmpty()：是否为空

  • clear()：清空

java.util.TreeSet 多的函数：

  • ceiling(key)：返回大于等于 key 的最小元素，不存在则返回 null
  • floor(key)：返回小于等于 key 的最大元素，不存在则返回 null

Map

接口：java.util.Map<K, V>

实现：

  • java.util.HashMap<K, V>：哈希表

  • java.util.TreeMap<K, V>：平衡树

函数：

  • put(key, value)：添加关键字和其对应的值

  • get(key)：返回关键字对应的值

  • containsKey(key)：是否包含关键字

  • remove(key)：删除关键字

  • size()：返回元素数

  • isEmpty()：是否为空

  • clear()：清空

  • entrySet()：获取 Map 中的所有对象的集合

  • Map.Entry<K, V>：Map 中的对象类型

  • getKey()：获取关键字

  • getValue()：获取值

java.util.TreeMap<K, V>多的函数：

  • ceilingEntry(key)：返回大于等于 key 的最小元素，不存在则返回 null

  • floorEntry(key)：返回小于等于 key 的最大元素，不存在则返回 null

使用场景：集合操作元素，简单逻辑

set 覆写 equals()

要正确使用List的contains()、indexOf()这些方法，放入的实例必须正确覆写equals()方法

编写 equals 方法

因此，我们总结一下equals()方法的正确编写方法：

  1. 先确定实例“相等”的逻辑，即哪些字段相等，就认为实例相等；
  2. 用instanceof判断传入的待比较的Object是不是当前类型，如果是，继续比较，否则，返回false；
  3. 对==引用类型==用Objects.equals()比较，对==基本类型==直接用==比较。

Map 覆写 equals()和 hashCode():

  1. 因为在Map的内部，对key做比较是通过equals()实现的，这一点和List查找元素需要正确覆写equals()是一样的，即正确使用Map必须保证：作为key的对象必须正确覆写equals()方法。

  2. key计算索引的方式就是调用key对象的hashCode()方法，它返回一个int整数。HashMap正是通过这个方法直接定位key对应的value的索引，继而直接返回value。

Objects.hash()内部实现主要为每个类型的哈希值乘上一个质数 31 累加。

面试

  1. List，Set，Map 三者的区别？
  • List：有序，可重复
  • Set：无序，不可重复
  • Map：无序，（键唯一，值可重复），存储键值对（key-value）
  1. List，Set，Map 有哪些类，底层数据结构？
  1. List:
    • ArrayList: 基于动态数组实现。
    • LinkedList: 基于双向链表实现。
    • Vector: 类似于ArrayList，但是是线程安全的，性能差，不建议使用。
    • Stack: 继承自Vector，表示栈结构。
  2. Set:
    • HashSet: 基于哈希表实现，不保证元素的顺序，允许null元素。
    • LinkedHashSet: 基于哈希表和链表实现，维护插入顺序。
    • TreeSet: 基于红黑树实现，保证元素有序（按照自然顺序或者指定的Comparator）。
  3. Map:
    • HashMap: 基于哈希表实现，键值对无序，允许null键和null值。
      • 哈希表：数组 + 链表 + 红黑树（jdk1.8 后）
    • LinkedHashMap: 基于哈希表和双向链表实现，保证插入顺序。
    • TreeMap: 基于红黑树实现，按照键的自然顺序或者指定的Comparator进行排序。

  1. 哪些是线程安全的？怎么解决？

    ArrayList 和 Vector:

    • ArrayList：不是线程安全的，多线程环境下需要手动同步访问。
    • Vector：是线程安全的，因为它的每个方法都使用了synchronized关键字进行同步，所以性能通常较差。

    ConcurrentHa shMap 是如何保证线程安全的？

    • JDK 1.7 ： Segment 分段锁

    • JDK 1.8 ： CAS 和 synchronized

  1. JDK 1.7 及之前版本：

    ConcurrentHashMap使用了分段锁（Segment）的机制来保证线程安全。具体实现方式如下：

    • 整个哈希表被分成了一定数量的段（Segment），每个段内部是一个独立的哈希表（数组），称为分段数组。
    • 每个分段数组默认是 16 个段，每个段是一个独立的哈希表，可以独立进行操作，从而实现了并发访问。
    • 每个段内部的操作都是线程安全的，通过对每个段内部的操作使用锁来实现同步，但不同段之间的操作可以并发进行，从而提高了并发性能。

  2. JDK 1.8 及之后版本：

    主要使用了 CAS（Compare and Swap）操作和synchronized关键字。具体实现方式如下：

    • ConcurrentHashMap内部使用了一种称为数组+链表+红黑树的数据结构来存储键值对，类似于普通的HashMap。
    • JDK 1.8 引入了红黑树来解决链表过长导致性能下降的问题，当链表长度超过一定阈值时，会将链表转换为红黑树，从而提高查找、插入和删除操作的性能。
    • ConcurrentHashMap使用了 CAS 操作来进行并发控制，通过 CAS 操作来更新节点，避免了对整个数据结构进行加锁，提高了并发性能。
    • 在需要进行结构修改的情况下，仍然使用synchronized关键字来确保线程安全，但是仅针对修改相关的部分加锁，而不是对整个数据结构加锁，从而降低了锁的粒度，提高了并发性能。

  1. HashMap 查询，删除的时间复杂度

    没有哈希冲突的情况 O(1)

    转链表的情况 O(N)

    链表转红⿊树的情况 O(logN)

    • 某些情况下可能需要对红黑树进行平衡调整，导致删除操作的时间复杂度略有增加

  2. HashMap 的⻓度为什么是 2 的幂次⽅？

    在计算元素的哈希值与数组长度取模时，可以用位运算替代取模操作，这样可以提高计算效率。

  3. HashTable 和 HashMap?

  • 线程安全性：HashMap 是非线程安全的，而 Hashtable 是线程安全的。

  • null 值和 null 键的处理：HashMap 允许 null 值和 null 键，而 Hashtable 不允许，会抛出 NullPointerException。

  • 继承的抽象类不同。

  1. HashMap 和 HashSet ：

  • 内部实现机制：HashSet 实际上是通过 HashMap 来实现的，它的元素被存储在 HashMap 的键位置上，值为固定的一个对象。

  • 存储元素的方式：HashMap 存储的是键值对（key-value pairs），而 HashSet 存储的是唯一的元素集合。

  • 重复元素的处理：HashMap 可以存储键值对，因此键可以重复但值不能重复；而 HashSet 不允许存储重复的元素，如果插入相同的元素，后续的插入操作会被忽略。

  1. HashMap 和 TreeMap 的区别：

    • 内部实现方式：HashMap 使用哈希表来存储键值对，它不保证键值对的顺序；而 TreeMap 使用红黑树来存储键值对，并根据键的自然顺序或者比较器的顺序来维护键值对的顺序。

    • 性能：HashMap 的查询、插入和删除操作的平均时间复杂度为 O(1)，而 TreeMap 的这些操作的时间复杂度为 O(log n)，其中 n 是键值对的数量。

    • 顺序保证：HashMap 不保证键值对的顺序，而 TreeMap 会根据键的排序规则来维护键值对的顺序，因此 TreeMap 中的键值对是有序的。
